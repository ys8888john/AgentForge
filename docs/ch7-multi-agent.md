# Ch7 多智能体（Multi-Agent）

> 对应《Agentic Design Patterns》第七章。agentOS 实现位置：
> 后端 `agentd/src/patterns/multi_agent.rs` + `events.rs`（`Agent` 事件）
> + `main.rs`（`parse_multi_agent` / 分发 / SSE 映射）；前端 `web/app/page.tsx`（「多智能体」模式）。

## 1. 核心思想

让**多个扮演不同角色的 Agent** 就同一个任务并行给出各自视角的观点，再交由一个「汇总 Agent」综合成最终答复。
相比 Ch3 并行化（多个无角色标签的 worker 并行），多智能体的关键在**角色分工**——每个 Agent 有明确的
身份/视角（如「科学家」「产品经理」「风险官」），这正是真实 multi-agent 系统的常见形态：用「视角多样性」
换取更周全、更少盲点的结论。

```
   共享任务
     │
     ├──────────┬──────────┬──────────┐
     ▼          ▼          ▼          ▼
   Agent 0   Agent 1   Agent 2   …（并行，各自独立发言）
   （科学家） （产品经理） （风险官）
     │          │          │
     └──────────┴──────────┴──────────┘
                       │
                       ▼
              汇总 Agent：综合各方 → 最终答复
```

## 2. 与 Ch3 并行化的区别

| 维度 | Ch3 并行化 | Ch7 多智能体 |
|------|-----------|--------------|
| 角色 | 无（都是"worker"，同一类审查） | 有（每个 Agent 有独立 persona / 视角） |
| 适用 | 同一维度多角度评审（如三条审查） | 跨职能分工（科学/产品/风险/…） |
| 提示 | 各 worker 各自 prompt | 角色设定 + 共享任务 |
| 事件 | `worker` | `agent` |

两者底层都用 `futures::future::join_all` 并发调用 LLM。

## 3. 实现方式

### 角色定义
每个 Agent 由 `name`（角色名）+ `persona`（角色设定/视角提示）组成。请求不提供 `agents` 时，
后端回退到内置三角色（科学家 / 产品经理 / 风险官），保证开箱即用。

### 执行流程（`run`）
1. **并行发言**：遍历角色，逐个 `yield Agent{index,name}` 报到，再调用 `run_one_agent` 取得该角色观点，
   按字符切片流式回放为 `Token`。各角色的 `Reasoning`（思考）不计入观点文本，避免噪声污染汇总。
2. **汇总**：用 `join_all` 再并发取一次各角色观点（避免复用已被流式消费的结果），构造汇总提示，
   由「汇总 Agent」综合成最终答复并流式输出；最后 `Done(final_text)`。
   - 汇总提示可用请求里的 `synthesis_prompt` 自定义（支持 `{task}` / `{views}` 占位符），缺省用内置通用模板。

> 说明：当前实现是「单 LLM 多角色」的轻量多智能体——同一模型按不同 persona 扮演多个 Agent，
> 体现角色分工与汇总的核心思想，且天然并行。更重的形态（每 Agent 独立进程/独立模型、Agent 间消息传递、
> 辩论/协商）属 Ch15+ 生产化范畴，本项目暂不展开。

## 4. 事件契约（SSE）

| 事件 | data | 含义 |
|------|------|------|
| `agent` | `index:name` | 某个 Agent 开始工作（含最后的「汇总 Agent」，index = 角色数） |
| `token`/`thought` | 文本 | 该 Agent 的流式观点 / 汇总 Agent 的思考 |
| `done` | 文本 | 汇总后的最终答复 |
| `error` | 文本 | 执行异常 |

## 5. 前端「多智能体」模式

- 模式按钮：工作台 → 多智能体
- 配置项：可增删角色、编辑每个角色的 `name` 与 `persona`（视角设定）；默认三个角色
- 输出区：
  - `🤖 智能体 N · 角色名`（紫色虚线标签，对应 `agent` 事件）
  - 随后该角色观点流式 `token`；最后「汇总 Agent」综合出最终答复
  - 同样受全局「开启思考过程」「思考过程默认展开」设置影响

## 6. 验证示例（curl）

```bash
curl -N -X POST http://localhost:8090/api/sessions/<sid>/run \
  -H 'Content-Type: application/json' \
  -d '{
    "input": "应不应该大力发展自动驾驶出租车？",
    "pattern": "multi_agent",
    "agents": [
      {"name":"科学家","persona":"你是一位交通工程研究者，用数据与机理分析安全性、效率与环境影响。"},
      {"name":"产品经理","persona":"你是一位出行产品经理，从用户体验、成本与商业化角度分析。"},
      {"name":"风险官","persona":"你是一位安全与伦理审查者，专挑责任归属、隐私与失业风险。"}
    ]
  }'
```

预期事件序列：`agent`(科学家) + `token`* → `agent`(产品经理) + `token`* →
`agent`(风险官) + `token`* → `agent`(汇总 Agent) + `token`* → `done`。

## 7. 常见坑

- **角色设定要「有冲突」才好用**：三个同质视角（如三个都做事实核查）会产出雷同观点，汇总价值低；
  让角色覆盖不同职能/立场（科学 vs 产品 vs 风险）才能体现多智能体优势。
- **观点文本别带思考噪声**：`run_one_agent` 只收 `Chunk::Content`、丢弃 `Reasoning`，
  否则 qwen3 的长思考会混进观点、干扰汇总。
- **角色数要适度**：每多一个角色就多一次 LLM 调用，角色过多会显著拉长总耗时（本实现为顺序触发各角色、
  但每次都是独立流式调用，体验上仍按角色依次展示）。
